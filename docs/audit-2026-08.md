# Audit — August 2026

A full read of the workspace: code quality and performance, the HyDE
integration, and the Hyprland integration. Each finding was verified against
the code before it was written down. Items are ranked by impact within each
section. Status boxes track execution; a checked box means the fix landed on
`main` with green local checks.

## 1. Live defects

### 1.1 Keyboard layout indicator wired to the wrong events
`core/src/adapters/hyprland_client/listeners/keyboard.rs`

The layout-changed emission is registered on the *layer closed* handler and
the configuration-changed emission on the *monitor added* handler. The
`hyprland` crate provides a layout-changed handler (Hyprland's `activelayout`
event) and a config-reloaded handler. As written, the indicator refreshes when
a menu closes or a monitor is plugged in; a layout switch is reflected only by
accident.

- [x] Subscribe to the layout-changed and config-reloaded events.

### 1.2 Special-workspace events wired to the wrong events
`core/src/adapters/hyprland_client/listeners/workspace.rs`

Special-changed is mapped from *layer opened* and special-removed from
*monitor removed*. The crate provides dedicated changed-special and
special-removed handlers.

- [x] Subscribe to the dedicated special-workspace handlers.

### 1.3 Special workspaces can never render as active
`core/src/adapters/hyprland_client.rs`

The monitor snapshot hardcodes the special-workspace id to none, while the
workspaces module decides special-workspace activity by comparing exactly that
field. The `hyprland` crate exposes the monitor's special workspace; it is
simply never read.

- [x] Fill the special-workspace id from the monitor data.

### 1.4 The top link of the HyDE font chain can never fire
`proto/src/theme_source/font.rs`

The font chain feeds HyDE's `config.toml` into a flat `KEY="value"` parser.
Modern HyDE writes sectioned TOML (`[waybar]` with `font`/`scale` keys), so
the highest-priority source never matches. HyDE's own tooling reads the flat
export the `hyde-config` daemon generates at `$XDG_STATE_HOME/hyde/config`
(`export SECTION_KEY=value` lines) — hydebar should read the same file.

- [x] Read the flat state export; keep the TOML path as a fallback.

### 1.5 Window title goes stale on in-place title changes
`core/src/adapters/hyprland_client/listeners/window.rs`

No subscription exists for the title-changed event of the already-focused
window (Hyprland's `windowtitlev2`). The active-window event only fires on
focus changes, so browser tab switches, editor file switches and terminal
directory changes do not reach the bar until focus moves.

- [x] Subscribe to title-changed and forward it to the window-title module.

### 1.6 Tray registers, owns the watcher name, renders nothing
`core/src/modules/tray.rs`

The module starts the tray service, which claims the StatusNotifierWatcher
D-Bus name — blocking any other tray from taking it — while its view returns
nothing and the tray menu can never open. Either the GUI view gets finished or
the module must not register.

- [x] Decide: finish the view or stop registering while unfinished.

## 2. Performance and code quality

### 2.1 Blocking Hyprland IPC on the UI update thread
`core/src/adapters/hyprland_client/sync_ops.rs`

Every synchronous port call spawns a fresh OS thread and blocks the caller
with a 2 s timeout × 3 attempts + backoff — up to ~6.5 s of frozen bar on an
unresponsive socket. Callers sit on the iced update thread and fire on every
focus change and workspace event. Additionally, every event triggers a full
re-poll (three IPC round-trips) although the events already carry their data.

- [x] Resolve snapshots on the listener runtime and deliver resolved data in
      the message; reuse one worker instead of a thread per request.

### 2.2 Four separate event-socket connections
`core/src/adapters/hyprland_client/listeners/`, `core/src/outputs.rs`

Window, workspace and keyboard listeners plus the blur guard each hold their
own connection and supervisor; every compositor event is parsed four times.
The crate offers an async event stream suitable for one multiplexed
connection with an internal fan-out.

- [x] Collapse to a single connection.

### 2.3 Themes menu re-reads and re-hashes every wallpaper on each open
`core/src/modules/themes.rs`, `proto/src/theme_source/swatch.rs`

Opening the menu reads each theme's full wallpaper into memory and SHA-1s it
to locate the cached palette — tens of MB per open, no mtime/size memo. The
catalogue (network JSON + capability probe subprocess) also reloads on every
open.

- [x] Cache swatches keyed by theme + wallpaper mtime/size; load the
      catalogue once per session with explicit refresh.

### 2.4 Compositor look: subprocesses under a global lock, polled on a 1 s TTL
`proto/src/compositor_look.rs`

A cache miss spawns four `hyprctl getoption` processes while holding the
global mutex, on the UI thread during config reload. Hyprland emits a
config-reloaded event that should invalidate the cache instead of a TTL.

- [x] Compute outside the lock, batch the reads, invalidate on the
      config-reloaded event.

### 2.5 System-info sampler: blocking IO on the async runtime, samples everything
`core/src/modules/system_info.rs`

The sampling loop runs as an async task on the 4-thread runtime yet performs
statvfs per mount, network refresh and a full hwmon/DRM sysfs pass — every
1–5 s — regardless of which readouts the layout actually shows.

- [x] Move sampling to blocking context; skip unrendered metric families.

### 2.6 Config watcher does blocking IO inline on the async runtime
`core/src/config/watch/interpret.rs`

The watcher loads and parses the config (file reads, TOML parse, theme load
including subprocess calls) inline in its async task. The sibling theme
watcher wraps identical work in a blocking task, with a doc comment explaining
why — the two paths drifted.

- [x] Wrap the load in a blocking task, mirroring the theme watcher.

### 2.7 Icon glyph overrides leak on every config reload
`core/src/components/icons/theme.rs`

Configured glyphs are leaked to obtain a static lifetime on every appearance
refresh; a HyDE theme switch reloads several times in a burst, leaking each
time. The font-family code already interns via a process-wide set — reuse
that.

- [x] Intern glyphs in a process-wide set.

### 2.8 Event bus drops module events when full
`core/src/event_bus.rs`

Capacity is fixed at 64; only redraw/popup coalesce, and only against the
tail. A burst can silently discard module events, leaving stale UI.

- [x] Coalesce per event kind instead of dropping.

### 2.9 Unbounded native→async channels
`core/src/services/` (audio backend, PipeWire privacy, iwd
events, notifications)

Native threads push state snapshots into unbounded channels; a stalled
consumer grows them without bound.

- [x] Bounded channels with drop-oldest/coalesce for snapshot events
      (pipewire and the audio bridge; the one-shot signal channels stay).

### 2.10 Heavy message variants cloned through the bus
`core/src/services.rs`, `core/src/modules/control_center.rs`

Service init events carry the whole service state by value through cloneable
messages. The tray module already boxes its event payload; the five
control-center services do not.

- [x] Box the service event payloads.

### 2.11 Per-frame and per-event allocation nits

- New HTTP client per weather/gallery request, no timeout — a hung connection
  stalls the weather loop indefinitely. Share one client with a timeout.
- Clock formats its string on every view call. Cache and invalidate on tick.
- Theme construction allocates names and rebuilds the faded palette per frame.
- Frame messages come from a fixed 16 ms timer (beats against 144 Hz); the doc
  claims a compositor callback. Drive from redraw requests.
- Whole-config deep equality runs twice per reload before the pointer check.
- Network refresh clones the service and its access-point list every 2 s while
  the menu is open.
- The system-info window model is built twice per frame while animating
  (measurement + render); same for settings and themes menus.
- The orphan reaper scans all of /proc every 60 s; restrict to known groups.
- Blur restatement probes up to 6 subprocess spellings repeatedly; memoize the
  accepted spelling like the dispatch dialect already does.
- Notification server locks unwrap on poison; recover like the compositor-look
  cache does.

- [ ] Work the list top to bottom.

### 2.12 Structural debt

- The ports layer covers only Hyprland; D-Bus, PipeWire, PulseAudio,
  filesystem and subprocess access are reached directly. Consequence: 15 test
  modules are compiled out behind a broken-tests feature and 10 more are
  ignored. Extend ports gradually as modules are touched.
- Keybinding config is parsed and ignored; keys are hardcoded and bare
  letters fire navigation messages even while a text input holds focus.
- Keyboard-opened menus anchor to a hardcoded 1920×1080 geometry.
- Six modules span 2–5 k lines as single files; split along their existing
  inline module boundaries when next modified.

- [ ] Address opportunistically; keybindings and menu anchoring first.

## 3. Deeper HyDE integration

### 3.1 Watch what is read
`core/src/config/theme_watch/sources.rs`

The watcher covers wall palette, state file and waybar CSS. Unwatched but
read: HyDE `config.toml`, the flat state export, the state Hyprland override,
the active theme's `hypr.theme`, the env-theme file, the layout files.
Editing any of these requires a bar restart today.

- [x] Extend the watch set to every read source.

### 3.2 Wallpaper picker
`core/src/modules/wallpaper.rs`

HyDE exposes a JSON wallpaper listing (path, hash, four thumbnail variants,
palette file) with thumbnails pre-rendered in the cache. The module currently
offers only next/previous. A thumbnail grid with palette swatches and backend
selection would be a first-of-its-kind HyDE surface.

- [ ] Build the picker menu on the listing.

### 3.3 Local gallery database
`core/src/modules/themes.rs`

The gallery fetches screenshots from the network although HyDE maintains a
local gallery database with per-theme screenshots. Use the local database
first, network as fallback.

- [ ] Prefer the local database.

### 3.4 Use more than 7 of the 44 wallbash colours
`proto/src/theme_source/dcol/roles.rs`

All 44 keys are parsed; 7 survive. The 10-slot workspace colour array
collapses to one colour under HyDE. Map accent ladders to workspace and
module tints.

- [ ] Widen the role mapping.

### 3.5 First-class wallbash target

Ship a wallbash template + the documented skip-template setting instead of the
current theme-switch shim, making HyDE colour hydebar natively on every
wallpaper change.

- [ ] Add the template and installer wiring.

### 3.6 HyDE settings as defaults

Weather location/units, battery thresholds, volume/brightness steps and media
player prefs already live in HyDE's config; the bar ignores them (weather
defaults to London). Layer them under user config like the appearance overlay
already does.

- [ ] Layer HyDE per-feature settings.

### 3.7 Labelled-but-empty modules

The layout mapper knows night-light and keybind-hint labels with no module
behind either. HyDE ships the night-light state file and a keybindings file
whose own header asks for a GUI parser; a structured enumerator binary and a
rofi fallback exist.

- [ ] Night-light toggle/slider; keybind cheat-sheet overlay.

### 3.8 Smaller items

- GTK/icon/cursor theme from HyDE's dconf snapshot for tray/launcher icon
  lookup.
- Updates menu: show installed HyDE version and pending-change log from the
  local state files (only the clone path is read today).
- Theme list order: the bar sorts alphabetically while HyDE's switcher walks
  its sort file — the lists disagree.
- Capability probe once via the CLI's surface instead of per-feature guessing;
  emoji/glyph pickers, zoom, tabs and reload become one-line menu actions.
- Register the bar's config in HyDE's config registry so the desktop's config
  tool lists it.

- [ ] Work the list as modules are touched.

## 4. Deeper Hyprland integration

### 4.1 Per-monitor active workspace

The snapshot records one global active workspace; on multi-monitor the other
monitor's visible workspace draws as inactive. Monitor data carries its
active workspace and focus flag — model visible vs focused like the classic
waybar split.

- [x] Extend the monitor snapshot and workspace styling.

### 4.2 Urgent windows

The urgency event exists in the crate; the bar already has an attention
mechanism. Connect them so a demanding background window pulses its
workspace.

- [x] Wire urgency → workspace attention.

### 4.3 Fullscreen-aware bar

The fullscreen event enables the roadmap's auto-hide: drop or hide the bar
when the active workspace goes fullscreen.

- [ ] Subscribe and gate the layer.

### 4.4 Compositor-authoritative screenshare indicator

The screencast event distinguishes monitor from window shares and catches
captures PipeWire monitoring misses; feed the privacy module a second source.

- [ ] Add the source.

### 4.5 Extend the compositor look

Borders, active-border colour, blur enablement and shadows are readable the
same way rounding already is; skip the bar's own blur request when blur is
globally off, refresh on the config-reloaded event rather than a TTL.

- [x] Extend the look struct and its consumers (blur gate; borders/shadows
      still open).

### 4.6 Typed IPC instead of subprocess calls

Five call sites shell out where the crate has typed equivalents (options,
monitor listing, notifications). Startup and the notification path lose
process spawns; monitor parsing loses two hand-rolled JSON parsers.

- [ ] Replace call sites — blocked by the crate: its monitor data lacks the
      physical dimensions the auto-scale needs, and its notify colour type
      has no public constructor. Revisit on the next hyprland-rs release.

### 4.7 Further

- Window-group tab strip (no waybar equivalent — a differentiator).
- App icon by window class beside the title; badges for xwayland/floating/pinned.
- Direct hyprpaper IPC (a typed client ships enabled and unused in the crate).
- Colour picker beside the screenshot module.
- Keybind hints from compositor bind data, submap-aware, pairing with the
  existing submap module.
- Monitor hotplug/VRR from compositor events to invalidate geometry caches
  precisely.

- [ ] Pick up after the items above land.
